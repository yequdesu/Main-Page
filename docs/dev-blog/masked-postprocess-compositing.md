# 闭合区域后处理的实现注意事项

本文记录本项目中“只在自定义闭合区域内应用 WebGL 后处理”的稳定实现方式。当前实验是第一幕中央正方形区域内的 RGB 二值化，位置实现见 [`WebglCollagePostProcess.tsx`](../../src/r3f/WebglCollagePostProcess.tsx)。

## 1. 不要把局部效果误写成全屏效果

后处理通常需要先把场景渲染到 `WebGLRenderTarget`，再用全屏四边形采样这张纹理。即使 shader 中只修改遮罩内的像素，遮罩外的像素也仍然会经过：

1. 离屏渲染。
2. 纹理采样。
3. 颜色空间转换。
4. 最终全屏合成。

其中任一环节不一致，遮罩外就可能出现亮度、对比度或色相变化。因此，“shader 中使用 `mix(original, effect, mask)`”并不自动等于“遮罩外完全不受影响”。

## 2. 最稳妥的合成方式：原场景先画，效果透明叠加

对于要求遮罩外保持原样的局部效果，采用以下顺序：

```text
场景 -> 默认 framebuffer
场景 -> 离屏纹理
离屏纹理 + 闭合遮罩 -> 透明后处理四边形 -> 默认 framebuffer
```

正方形实验在没有其他全屏后处理时使用这一分支：

- 先正常绘制场景。
- 后处理四边形只在正方形内输出不透明结果。
- 正方形外输出透明度 0。
- 绘制叠加层时关闭 `autoClear`，避免清掉刚刚绘制的原场景。

这样即使后处理 shader 的颜色编码存在微小差异，差异也只会出现在闭合区域内部。

## 3. 遮罩必须是独立的屏幕空间资源

闭合区域建议单独使用一个 mask render target，而不是把遮罩逻辑混进场景材质：

- 遮罩材质只输出 `0` 或 `1`。
- 不参与深度测试和深度写入。
- 硬边界使用 `NearestFilter`，柔和边界才使用 `LinearFilter` 或 shader 插值。
- 遮罩与场景使用同一套屏幕坐标和 UV 约定。

当前正方形通过屏幕像素坐标计算：

```text
screenPoint = (uv.x * width, (1 - uv.y) * height)
```

这里的 `1 - uv.y` 不可遗漏，否则遮罩会发生上下翻转。

## 4. 颜色空间要明确分层

离屏 render target 与默认 framebuffer 的输出颜色空间不同，不能凭经验混用：

- 场景离屏纹理按线性空间处理。
- 二值化阈值应明确是在 `linear RGB` 还是 `sRGB` 上计算。
- 当前实验是在离屏纹理的线性 RGB 通道上使用固定阈值 `0.42`。
- 只有最终输出到屏幕时才执行线性到 sRGB 的编码。

常见错误包括：

- 对已经是 sRGB 的纹理再次执行 sRGB 编码，导致整体变亮。
- 对线性纹理直接按 sRGB 阈值判断，导致二值化边界不符合预期。
- 场景直绘路径和后处理路径使用不同的 tone mapping 或 output color space。

如果要求遮罩外像素逐像素保持一致，优先使用“原场景直绘 + 透明后处理叠加”，不要依赖全屏 shader 对原像素进行回写。

## 5. 透明叠加时不能清屏

局部后处理的叠加阶段必须满足：

- 原场景已经存在于当前 framebuffer。
- 后处理材质 `transparent: true`。
- 遮罩外 alpha 为 `0`。
- 叠加绘制前后正确保存并恢复 `renderer.autoClear`。

如果在绘制后处理四边形前调用 `clear()`，原场景会被清空；如果不关闭 `autoClear`，`renderer.render()` 也可能在绘制叠加层前自动清屏。这是局部效果“看起来像整屏重绘或变黑”的高频原因。

## 6. 多种后处理要分清作用域

后续如果加入灰度、噪波、颗粒、反色或色调映射，应为每种效果明确作用域：

```text
squareMask       -> 只作用于正方形
circleMask       -> 只作用于圆形
rayCorridorMask  -> 只作用于射线夹角区域
globalEffect     -> 明确允许作用于全屏
```

不要把多个 mask 直接覆盖写入同一个通道，除非已经明确需要 `union`、`intersection` 或 `xor`：

- 并集：`max(a, b)`。
- 交集：`min(a, b)`。
- 异或：`abs(a - b)`。
- 抵消关系：单独定义组合规则，不要依赖绘制顺序碰巧得到结果。

## 7. 分辨率与响应式布局

场景 render target 通常使用 `CSS 尺寸 * pixelRatio`，而 mask 的几何判断常使用 CSS 像素。两者必须通过 UV 归一化对应起来：

- resize 时同步更新所有 render target。
- 同步更新 mask 的屏幕分辨率 uniform。
- 正方形尺寸应使用 `min(width, height)` 的比例，避免宽屏下变成长方形。
- 不要把 CSS 像素坐标直接当作 render target 的物理像素坐标使用。

## 8. R3F demand 模式下的刷新

本项目 Canvas 使用 `frameloop="demand"`。后处理涉及动画或滚动时，必须保证对应状态变化会触发 `invalidate()`，否则 shader uniform 虽然更新，画面也不会刷新。

静态闭合区域只需要在尺寸变化或状态变化时刷新；如果后续加入噪波时间、扫描动画或动态边界，则需要：

- 将时间驱动加入现有的连续刷新条件，或
- 在动画帧中主动调用 `invalidate()`。

## 9. 生命周期与清理

新增以下资源时必须在 cleanup 中释放：

- `WebGLRenderTarget`。
- `ShaderMaterial`。
- `PlaneGeometry`。
- 独立的 mask scene 与 quad。
- CanvasTexture 或其他纹理。

否则反复热更新、路由切换或组件重挂载时会出现显存增长和旧材质继续参与渲染的问题。

## 10. 验证清单

实现闭合区域后处理后，至少检查以下状态：

- 区域外的背景亮度、色相和对比度与未启用效果时一致。
- 区域边界没有透明缝、黑边或反向采样。
- 窗口缩放和不同 pixel ratio 下，闭合区域仍位于预期位置。
- 后处理启用和关闭之间没有清屏闪烁。
- 与其他遮罩叠加时，组合关系符合明确的并集、交集或抵消规则。
- 不存在 focus HUD 时，focus mask 不会使用上一次残留数据。
- `npm run build` 与 `git diff --check` 通过。

## 结论

“闭合区域内应用后处理”的关键不是只写一个区域判断，而是同时控制：

1. mask 的空间范围。
2. 场景与后处理的颜色空间。
3. 原场景与后处理的绘制顺序。
4. 透明叠加时的清屏行为。
5. 多个 mask 的组合规则。

对遮罩外必须保持原样的效果，优先采用透明叠加路径；只有确实需要全屏统一处理时，才使用完整的全屏合成路径。
